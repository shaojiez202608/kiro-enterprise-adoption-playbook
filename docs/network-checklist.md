# 网络排查清单（FR-5）

> Prototype，不用于生产。核实日期：**2026-10-20**。事实编号见 `docs/architecture.md`。端点清单以官方页面为准，本文不复制整表（D-10）。

## 1. 放行清单

官方页面：https://kiro.dev/docs/privacy-and-security/firewalls/ （F-22）

按团队实际使用的界面，逐组核对：

- [ ] 核心 URL（所有 Kiro 产品都需要）。
- [ ] 所用界面的 URL：IDE、CLI、Web 各有一组。
- [ ] 登录方式对应的 URL：IAM Identity Center（需替换为自己的目录 ID/别名和区域）、外部 IdP 域名、社交登录。
- [ ] 遗留的 `q.<region>.amazonaws.com` 端点：官方说明目前仍需放行，直到弃用完成。
- [ ] 订阅管理相关 URL（仅非 Identity Center 的个人订阅需要）。
- [ ] 可选 URL（扩展、Powers/MCP 拉取 GitHub 内容等），以及团队 MCP 服务器自身需要访问的地址（例如 `npx` 拉取 npm 包）。
- [ ] 通配符规则：部分防火墙的通配符只匹配一级子域，官方页面列出了需要额外添加的多级通配符。

## 2. 代理

- [ ] IDE 与 CLI 遵循 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；IDE 也可在 **Settings > Proxy** 配置（F-22）。
- [ ] 登录时打开的是系统默认浏览器，走操作系统网络栈，**绕过** IDE/CLI 的代理设置。因此 Identity Center 相关 URL 和登录门户必须在网络层放行，不能只依赖 IDE 代理（F-22）。
- [ ] MCP 服务器进程是否继承代理环境变量，取决于具体服务器实现；需要时在 `mcp.json` 的 `env` 中设置（`env` 字段见 F-01）。

## 3. TLS 检查

- [ ] 官方排障页说明：部分用户能连、部分不能时，常见原因是企业防火墙的 TLS inspection（F-23）。
- [ ] 典型症状：登录成功后显示 "No profiles available"；客户端日志 `Failed to retrieve profiles` 且错误串为空；登录完成但聊天不可用（F-23）。
- [ ] 若怀疑 TLS 检查，与网络团队一起对照受影响用户与正常用户的网络路径和策略差异。官方没有给出「对哪些域名关闭 TLS 解密」的正式建议（U-05），本清单不做此建议。

## 4. 区分「网络问题」和「服务问题」

在受影响用户的机器上运行官方排障命令（F-23）：

```bash
curl -v https://runtime.us-east-1.kiro.dev
curl -v https://management.us-east-1.kiro.dev
```

| 现象 | 判断（依据 F-23） | 下一步 |
|---|---|---|
| TLS 握手成功（即使返回 HTTP 错误码） | 官方说明：网络连通（F-23）。注意：有 TLS 检查且本机信任企业 CA 时，握手同样会成功，因此握手成功**不能**排除 TLS 检查 | 排查建议（本仓库建议，非官方说法）：在 `curl -v` 输出中查看服务器证书的 issuer；若是企业自有 CA 而不是公共 CA，说明连接经过了 TLS 检查，按第 3 节与网络团队处理。否则收集客户端日志、版本、时间点，通过官方渠道反馈（F-38）；企业用户可联系 AWS Support |
| 连接超时或 TLS 错误 | 防火墙或代理问题 | 对照第 1–3 节，与网络团队排查 |
| 同一网络下部分用户正常、部分异常 | 多为用户网络配置差异（如 TLS 检查策略） | 对比两类用户的代理/证书/策略 |

说明：

- 上面两个命令使用的是 US East 端点；Kiro profile 在欧洲区域的组织，按官方放行清单中的对应区域端点测试（F-22）。
- 官方文档中未找到 Kiro 的服务状态页（U-15），本清单不提供状态页链接。

## 5. 降低断线影响

- [ ] 长任务使用云端会话：客户端断开不停止 agent，重新连接后回放记录（F-13）。
- [ ] Kiro Web 标签页在睡眠或网络变化后返回时会自动重连并回放离开期间的活动（F-16）。
- [ ] 需要不经公网访问 Kiro API 的场景，评估接口 VPC 终端节点（AWS PrivateLink），官方页面列出服务名（F-24）。
- 本地 IDE 会话断网后任务是否继续、如何恢复，官方未说明（U-07）。

## 6. 提交问题时附带的信息

- 客户端类型和版本（IDE / CLI / Web）、登录方式。
- 第 4 节两个命令的输出（去掉公司内部主机名和 IP）。
- 发生时间（UTC）与是否所有用户都受影响。
- 是否经过代理、是否有 TLS 检查（只写「有/无」，不写设备或产品名称）。
